# 变形算法的质量控制

## 策略边界

不要通过图标名称、注册表编号或已知图标组合选择算法。解析、配对、策略选择和渲染分别负责：

| 阶段 | 入口 | 约束 |
| --- | --- | --- |
| 输入规范化 | `ImageVectorAdapter.kt` / `StrokeOutline.kt` | 保留可见填充、描边及端点形状；只删除已证明无填充的退化路径 |
| 轮廓对应 | `MorphPlan.kt` 的 `matchContours` | 角色相容；填充轮廓不能重复分配；记录输入轮廓编号 |
| 策略选择 | `ContourStrategies.kt` | 按显式策略执行；满足条件才进入；否则回退并记录原因 |
| 插值与曲线还原 | `Interpolate.kt` / `CurveDetails.kt` / `SharedBoundary.kt` | 有限坐标、端点连续、中断连续；约束不能暗中改变公共区域 |

`MorphOptions.contourStrategy` 独立于 `transitionMode`：

- **标准轮廓**（`Standard`）：普通轮廓基线，关闭公共边界与孔洞连接启发式。
- **公共边界**（`SharedBoundary`）：默认策略，识别明确公共边界；不使用孔洞连接缝。
- **实验性孔洞连接**（`ExperimentalHoleOpening`）：显式启用孔洞连接，同时允许公共边界约束。未满足局部性、唯一父轮廓等条件仍回退。

描边中心线策略不受此填充轮廓选项影响。动画演示可直接切换三种策略，展开 **规划详情**，
查看输入对应、实际策略、约束数量、局部运动、连接缝及回退原因。编号指规范化后的轮廓，
不是矢量路径命令下标；描边展开可能合并轮廓，中断后的编号指当前快照。

## 日常验证

```powershell
./gradlew.bat verifyMorph --console=plain
```

执行桌面端几何性质和既有修复测试、桌面端测试、快速回归视觉对比、安卓端与浏览器端编译和公共接口检查。
不会启动浏览器测试。合并请求工作流在与现有基线相同的桌面系统上执行同一入口，并保留测试及视觉报告；工作流文件
在本机只能验证配置与对应任务，远端运行结果以持续集成为准。

性质测试与案例回归承担不同职责：

| 性质 | 测试 |
| --- | --- |
| 自身不动、等价起点/直线细分不改变画面、策略隔离 | `GeometryContractTest` |
| 旋转/平移对应、折叠检查、方向选择、整体运输 | `MorphPlanTest` |
| 不可见填充路径不干扰结果，描边与零有向面积图形不误删 | `ImageVectorAdapterTest` |
| 曲线端点、公共区域、连续多次中断 | `CurveDetailsTest` / `StationaryContourTest` |
| 拓扑增减与普通孔洞回退 | `MorphGeometryTest` |
| 搜索与关闭、设置、锁的六个方向及显式实验策略 | 演示应用的桌面端测试 |
| 全部注册图标、全部轮廓策略的自身对应，无旋转、无非有限值、无异常孔洞操作 | `CatalogContractTest` |

这不是任意曲线表示的完全不变性证明。例如缺少相同顶点、重排路径和不同参数化仍可能触发回退。
新的反例必须先归类到某条性质，再决定修改哪一阶段。

## 视觉回归

```powershell
./gradlew.bat :morph-playground:visualRegression --console=plain
./gradlew.bat :morph-playground:visualRegression '-Pmorph.visual.mode=candidate' --console=plain
```

报告：`morph-playground/build/reports/morph-visual/quick/index.html`，机器可读指标为同目录 `metrics.tsv`。
可按图标、策略和状态筛选，按变化/端点异常/公共像素偏移排序，查看保存参考、当前图和差异图。
每条记录附实际规划决策。候选生成模式只生成候选，绝不覆盖保存的基线。

差异图比较当前结果与历史基线的同一进度帧，不比较动画起点和终点：

- 灰色（`#eeeeee`）：像素差异未超过通道容差 `16/255`；全灰代表没有超出容差的变化，不是渲染失败。
- 粉色（`#ff0099`）：像素差异超过容差，标记需要审阅的位置，不直接判定动画错误。
- 「新增」：没有历史基线，不提供差异图。「有变化」也可能由图片尺寸不同引起。
- 「异常」：验证未完成，需查看规划说明与测试日志，不能视为通过。


- **快速回归**：10 对代表性图标及反向，3 种轮廓策略、极坐标与线性插值、自动旋转，共 120 个动画序列。
  覆盖中心线、多笔画、跨表示、曲线、多孔洞和拓扑变化。每序列保存 0/25/50/75/100% 帧，另检查两个近端点。
- **广域抽样**：快速回归加全部注册图标自身，以及固定步长 37 的双向配对，再覆盖三种旋转偏好。
  它是确定性广域抽样，不是所有两两组合；耗时和产物远大于快速回归。首次运行没有保存参考时使用候选生成模式。

```powershell
./gradlew.bat :morph-playground:visualRegression '-Pmorph.visual.suite=wide' '-Pmorph.visual.mode=candidate' --console=plain
```

指标包括基线像素差、近端点覆盖差、相邻关键帧面积变化、源/目标一致像素的中途偏移、背景孔洞数量变化。
后三项仅帮助排序：旋转、分裂、开孔本来就可能改变这些值，不能拿它们自动判定动画好坏。
报告目前不测帧率、所有连续时刻或所有自交；仍需审阅异常的中间帧与实跑动画。

对比使用 96 像素黑色图标白底，通道差大于 16/255 计为变化；任何这样的变化、新增/删除案例或清单差异都会令基线对比失败。
近端点单像素覆盖差超过 128/255 时计数，两端合计超过 8 会令候选生成模式和基线对比都失败。
这是固定测试分辨率下的容差，不能临时放宽来通过某次修改。渲染平台/依赖变动可能造成差异，应独立审阅。

## 基线审阅与修改准入

先阅读报告并公开当前图片，再单独更新参考链接：

```powershell
pnpm quality:publish
pnpm quality:promote --suite quick --reason '说明接受哪些变化及对应问题'
./gradlew.bat :morph-playground:visualRegression --console=plain
```

推广脚本要求填写原因；它不会替你判断视觉质量。初始参考仅固定当前行为（包含已知不足），不是给所有效果背书。
不要在失败的基线对比后自动运行推广命令。一次算法变更应提交：

1. 修改的阶段/策略及适用条件，是否改变默认行为。
2. 不依赖图标名称的性质测试与最小几何反例。
3. 快速回归报告；扩大策略适用范围时另附广域抽样报告及未验证范围。
4. 接受的视觉差异及理由，公共接口差异，性能或行为限制。

实验策略升级为默认必须单独审阅，不能作为单个图标修复的附带改动。未验证或无法解释的策略变化应保留为实验或回退。

## 网站质量中心

在仓库根目录执行 `pnpm dev:quality`，打开 [本地质量中心](http://127.0.0.1:8421/quality.html)。
此入口不编译或加载浏览器动画运行时；文档直接来自本文件，修改后自动更新。
视觉报告沿用桌面端渲染结果，不需要浏览器测试。

- `pnpm quality:report`：生成并对比快速回归报告；完成后在质量中心点击「刷新报告」。
- 本地服务直接读取 `morph-playground/build/reports/morph-visual/`，无需复制文件或重启服务。
- 快速回归 / 广域抽样分开显示；缺少报告或正在生成时明确提示，不把保存基线冒充当前结果。
- 页面显示模式、运行结果、序列数和完成时间。报告是该次运行的快照，代码修改后需要重新生成。
- 现有报告的筛选、规划详情、原图/当前图/差异图保留；可在质量中心内查看或独立打开。

`pnpm build` 将文档与已有报告复制进网站静态产物，未生成报告时仍可阅读文档。
网站发布工作流设置 `MORPH_SKIP_ANDROID=true`，不应用 Android 插件、不创建 Android target，因此无需准备 Android SDK；保留用于视觉报告的 JVM 和用于演示的 Wasm target。
本地也可设置此环境变量跳过 Android；按变量是否存在判断，恢复完整构建时应移除该变量（包括执行 `verifyMorph` 或发布库时）。
发布使用 `pnpm deploy:website`：先重新运行快速基线对比，再构建全站，最后部署到现有云端静态网站项目。
需要本机有效的云端部署账户登录，或对应的访问令牌与账户编号环境变量。
持续集成部署同样先执行快速基线对比，并强制检查已完成且通过的基线对比报告；失败则不部署，保留报告供审阅。
持续集成由两个发布工作流承担，不再单独设置质量工作流：`website.yml` 执行 JVM 单元测试、视觉基线对比和网站构建，通过后部署；`release.yml` 在库发布前执行 JVM 单元测试、API 兼容性检查，以及 Android、Wasm 编译检查。两者都会保留测试报告。
视觉基线对比继续在 Windows 上执行以保持平台一致；Ubuntu 上的库发布不重复对比 Windows 图片基线。本地仍可使用 `verifyMorph` 一次执行完整检查。

线上报告是随站点部署的静态快照。「刷新报告」只重新读取服务器上的产物，不会远程启动构建任务。

## 公开报告图片链接

先生成报告，再单独发布图片：

```powershell
pnpm quality:report
pnpm quality:publish
```

发布器采用桌面端 Kotlin 与 Ktor 客户端，从本机环境变量 `GITHUB_COOKIE` 读取登录凭据。
普通测试、报告生成和网站构建不会自动上传或发表评论。发布流程如下：

1. 按图片内容摘要去重，申请上传策略、上传图片数据并确认上传。
2. 将每批图片链接写入目标议题的临时评论，使附件可以公开访问。
3. 删除刚创建的评论，并取消订阅目标议题；删除失败时仍尝试取消订阅。
4. 使用不带登录凭据的客户端读取图片，并与本地字节比较；验证成功后才保存公开状态。

目标沿用参考实现的 [图片附件议题](https://github.com/gkd-kit/inspect/issues/46)。
图片上传到存储服务以及匿名验证时均不发送登录凭据，凭据也不会写入报告或缓存。

公开版报告保存为原报告目录下的 `public-index.html`，图片链接清单为 `public-images.json`。
本地上传缓存和待清理评论记录位于已忽略的 `.local/github-report-images/`。
同内容图片可复用链接；再次发布优先读取摘要校验通过的 `.cache/image/<附件ID>.png`，避免重复下载。首次公开仍强制进行匿名读取验证，成功后写入同一缓存。如果公开失败或清理未完成，命令失败，重新执行时优先清理遗留评论。
创建评论请求若因网络问题结果不明，不会自动重试创建，需检查目标议题后再执行。

质量中心刷新后会自动使用当前这次报告的公开图片版本。网站构建会复制公开版报告和链接清单，
不再打包该报告的图片目录；没有公开版本时继续使用本地图片。重新生成报告后需要再次执行发布命令，
不会将旧运行的链接清单自动套到新报告上。

这项功能只改变报告图片的存储方式，不修改算法、视觉基线或现有对比判定。

## 链接形式的历史基线

`visual-baselines/` 只提交案例清单、公开图片链接与摘要、渲染环境及审阅记录，不再保存图片文件。
每套基线的 `images.json` 以案例编号对应图片链接和 SHA-256 摘要；另记录规范化为换行符后的案例清单摘要，
避免不同系统的换行格式导致误报。迁移为链接不会改变已接受的图片内容或对比容差。

对比时使用匿名客户端下载图片，保存到已忽略的 `.cache/image/`，按链接中的附件编号定位缓存，并用内容摘要校验。
每次使用缓存前都校验摘要；损坏缓存重新下载，下载失败或图片摘要不匹配会使验证失败，不会当成新增案例或通过。
持续集成缓存同一目录；没有缓存时直接读取公开链接，不需要上传用的登录凭据。

基线更新脚本要求当前候选检查通过，且当前运行的图片已公开并通过内容验证。
它核对候选图片与发布时的摘要，更新链接清单并记录理由；普通对比不会修改清单。
公开版报告是展示产物，`visual-baselines/` 中经审阅的链接清单才是历史对比依据。

基线对比与图片发布共用 `.cache/image/<附件ID>.png`。`.cache/` 整体忽略，不提交到仓库。缓存命中只验证本地内容摘要，不保证远端链接此刻仍可访问；删除对应缓存可强制重新下载验证。

## 方形动画预览

视觉报告在「当前结果」和「差异图」之间提供方形动画预览。采用纯 Kotlin/JVM 编写的 APNG 编码器，
无需安装额外编码工具；文件扩展名仍为 `.png`。实现遵循 [PNG 动画格式规范](https://www.w3.org/TR/png-3/#11fcTL)。
当前使用完整帧、8 位灰度和白色背景，不包含时间戳等不稳定元数据。

默认先为搜索／关闭、主页／设置、锁定／向右解锁这三组的正反向生成预览，覆盖三种轮廓策略与两种插值，共 36 个案例。
每张动图为 96×96 像素、31 个采样帧，单程约 1 秒，首尾各停留约 300 毫秒，循环周期约 1.6 秒。
反向案例独立生成，不直接倒放正向动画。动画仅帮助人工观察，不改变原有静态基线或像素容差，也不测量真实应用帧率。

```powershell
# 默认生成代表案例的预览
pnpm quality:report
# 所有当前套件案例都生成预览（耗时和体积更大）
./gradlew.bat :morph-playground:visualRegression -Pmorph.visual.animation=all --console=plain
# 只生成静态报告
./gradlew.bat :morph-playground:visualRegression -Pmorph.visual.animation=none --console=plain
```

页面通过可见区域检测，在进入视口时播放，离开视口或页面隐藏时切换回静态首帧。
动画及首帧位于报告的 `animation/` 目录；发布命令会一起上传并验证原始字节，继续使用附件编号缓存。
公开版报告同时替换首帧和动画链接，不需要额外的浏览器动画运行时。
